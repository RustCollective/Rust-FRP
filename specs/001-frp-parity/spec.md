# Feature Specification: frp 功能对等（技术债务清偿基线）

**Feature Branch**: `001-frp-parity`

**Created**: 2026-10-10

**Status**: Draft

**Input**: User description: "HTTP/3 功能是否需要服务端和客户端同时兼容？如果是，先将原版 frp 功能都复现再推进 —— 盘点 Rust-FRP 与 frp 的功能差集，把技术债务按 SpecKit 规格落入文档，作为 M2.5–M2.9 的规格基线。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 用自有域名暴露内网 Web 服务（Priority: P1）

运维者希望把内网的一个 Web 服务（面板、博客、API）暴露到公网，并绑定自己的域名，而不是记一个 `ip:port`。他需要浏览器直接访问 `https://app.example.com`，证书由穿透服务端统一持有，内网服务本身不必改造、不必支持 HTTPS。同时同一个域名下的 HTTP 访问应自动可路由，服务端要能把真实访客来源信息透传给内网服务。

**Why this priority**: 这是 frp 使用频率最高的形态，也是 HTTP/3 网关的唯一地基——H3 只是在同一套域名路由之上换一个传输层。没有它，M3 无法起步；有了它，域名路由、证书终止、转发三条链路全部复用。当前实现只支持直连端口型代理，域名路由能力为零（证据见附录 A.1）。

**Independent Test**: 只实现本故事即可独立交付——注册一个 `http` 类型代理绑定测试域名，用 `curl -H 'Host: <域名>'` 打服务端的 vhost HTTP 监听端口，应完整拿到内网服务的响应；再用 `https` 类型注册，`curl --resolve <域名>:<端口>:<服务端IP> https://<域名>:<端口>/` 应在不关闭证书校验的前提下成功。

**Acceptance Scenarios**:

1. **Given** 服务端已配置 vhost HTTP 监听端口、客户端已注册 `http` 类型代理并声明域名 `app.example.com`，**When** 访客携带 `Host: app.example.com` 访问该端口，**Then** 请求被转发到客户端本地服务，响应原样返回，且内网服务收到的请求带 `X-Forwarded-For` 与 `X-Forwarded-Proto`。
2. **Given** 客户端已注册 `https` 类型代理并声明域名 `app.example.com`，**When** 访客用该域名的 TLS 握手（SNI）访问 vhost HTTPS 端口，**Then** 服务端按域名选出证书完成终止，并以明文 HTTP 把请求转发给客户端本地服务。
3. **Given** 没有任何会话注册 `unknown.example.com`，**When** 访客访问该域名，**Then** 得到 404，请求不会落到其他已注册代理上。
4. **Given** 会话 A 已注册域名 `app.example.com`，**When** 会话 B 尝试注册同一域名，**Then** 会话 B 收到注册失败与明确原因，会话 A 的映射不受影响。
5. **Given** 服务端配置了统一的子域名后缀，**When** 客户端只声明子域名标签 `app`，**Then** 该代理绑定到 `<app>.<后缀>` 并可被正常访问。

### User Story 2 - 暴露内网 UDP 服务（Priority: P2）

运维者需要把内网的 DNS、游戏服务、自建 QUIC/VoIP 服务暴露到公网。UDP 没有连接概念，一次会话由外部地址与端口共同确定，空闲后必须能自然回收，否则 NAT 表会被无意义地长期占用。

**Why this priority**: UDP 是 frp 基础代理类型里唯一完全缺失的一项（协议中已预留类型、实现缺失，证据见附录 A.1），影响面广，且与后续 HTTP/3 的 UDP 数据面共享同一套转发语义。

**Independent Test**: 注册一个 `udp` 代理指向内网回显服务，从公网发若干数据报并收到对应的回显；静置超过空闲阈值后，服务端侧该会话的资源被释放。

**Acceptance Scenarios**:

1. **Given** 服务端已放行目标 UDP 端口、客户端已注册 `udp` 代理，**When** 外部发包，**Then** 数据报被完整双向转发且边界不粘连。
2. **Given** 同一外部地址与端口持续发包，**Then** 全部落在同一条会话上；换一个源端口则视为另一条会话。
3. **Given** 一条 UDP 会话静置超过空闲阈值，**Then** 该会话被回收；同一源端口随后再发包时应能重新建立会话。
4. **Given** 服务端同时启用了两种隧道承载方式，**When** 分别在两种承载下注册 `udp` 代理，**Then** 两者的 UDP 转发行为一致。
5. **Given** 用户模式下某用户的端口授权区间不含目标 UDP 端口，**When** 该用户尝试注册，**Then** 注册被拒绝并给出与 TCP 路径同源的授权失败原因。

### User Story 3 - 让穿透链路具备生产可用的转发选项（Priority: P3）

运维者把真实业务挂到穿透链路上之后，会遇到 frp 用户在配置里习以为常的一批开关：链路带宽要限、重复内容要压缩、内网服务要靠 PROXY 协议拿到真实源 IP、后端挂了要能自动摘除、多个后端要能轮询、端口不想写死、同名代理的处置策略要明确。

**Why this priority**: 这些不是"新能力"，而是"从能用走向可运维"的缺口。缺了它们，Rust-FRP 无法承接 frp 的存量配置，只能用于实验。

**Independent Test**: 逐项独立可测——限速接入后用持续传输观测到速率被约束在阈值内；压缩接入后用大体积重复文本观测到隧道流量显著低于原始体积；PROXY 协议开启后内网服务读到真实源地址；健康检查开启后杀死内网服务，该代理在超时窗口内停止接入、恢复后自动重新接入；负载均衡组内两个后端都能收到请求；`remote_port` 留空时服务端分配端口并回告客户端。

**Acceptance Scenarios**:

1. **Given** 某代理开启带宽限制，**When** 持续传输，**Then** 实测速率不超过配置阈值，其余代理不受影响。
2. **Given** 某代理开启压缩，**When** 传输高重复度的载荷，**Then** 隧道内实际传输字节数显著低于载荷原始大小。
3. **Given** 某代理要求携带 PROXY 协议头，**When** 外部访客接入，**Then** 内网服务在业务数据之前读到包含真实源地址的 PROXY 头。
4. **Given** 某代理开启健康检查，**When** 内网服务停止响应，**Then** 超过失败阈值后该代理拒绝新接入；**When** 内网服务恢复，**Then** 该代理自动重新接入且无需重启客户端。
5. **Given** 两个会话注册在同一负载均衡组下，**When** 连续发起多次访问，**Then** 请求按配置策略分布到两个后端。
6. **Given** 客户端把 `remote_port` 留空（或填 0），**When** 注册成功，**Then** 服务端回告实际分配的端口，且该端口落在该用户授权区间内。
7. **Given** 已存在同名代理，**When** 新会话注册同名代理，**Then** 处置行为符合服务端配置（拒绝后者或抢占），且客户端能明确感知结果。

### User Story 4 - 不暴露公网端口的点对点穿透（Priority: P4）

运维者要临时访问内网的 SSH 或数据库，但不想在公网上开放任何端口。他希望把服务"发布"出来，只有持有同一密钥的访问方才连得上；如果双方 NAT 类型友好，更希望流量直接点对点走，不经过服务端中转。

**Why this priority**: frp 的 `stcp`/`sudp`/`xtcp` 是差集里最大的一块独立能力，但使用频率低于前三项，且实现复杂度最高（尤其打洞）。

**Independent Test**: 发布方注册一个密钥保护的代理（不开公网端口），访问方用相同密钥在本地建立监听；密钥不一致时连接被拒绝；密钥一致时访问方本地端口可直达发布方内网服务。若打洞成功，流量不经过服务端中转；打洞失败时应回退到服务端中转而非直接失败。

**Acceptance Scenarios**:

1. **Given** 发布方与访问方配置了相同密钥，**When** 访问方连自己的本地映射端口，**Then** 流量到达发布方内网服务。
2. **Given** 访问方密钥与发布方不一致，**When** 尝试接入，**Then** 连接被拒绝且不泄露发布方信息。
3. **Given** 发布方未开放任何公网端口，**Then** 外部扫描不到该服务。
4. **Given** 打洞条件不成立（NAT 类型不兼容），**When** 建立 XTCP 类连接，**Then** 自动回退到服务端中转路径，功能可用。

### User Story 5 - 用一个运维面看清并改动整个部署（Priority: P5）

运维者要在不改配置、不重启进程的前提下新增一个代理、下线一个故障代理、看到当前有哪些会话和多少流量；还要把监控系统接进来做告警；配置文件大到几百行时要能拆成多份；发布场景下希望有一个可视界面而不是只读日志。

**Why this priority**: 纯运维体验，不影响转发语义的正确性，但决定这套工具能否长期被托付给真实业务。

**Independent Test**: 管理接口默认只监听本机、需要凭证才能访问；查询接口能列出当前代理与会话并统计流量；触发重载后，客户端新增的代理立即可用且旧连接不中断；指标端点能被标准抓取器读取；配置拆分后行为与单文件一致。

**Acceptance Scenarios**:

1. **Given** 管理接口已启用，**When** 从非本机地址访问，**Then** 被拒绝；**When** 从本机带正确凭证访问，**Then** 返回代理与会话状态。
2. **Given** 客户端正在运行，**When** 修改配置文件并触发重载，**Then** 新增/变更的代理生效、被删除的代理下线，且已建立的转发连接不中断。
3. **Given** 已启用指标暴露，**When** 抓取该端点，**Then** 得到标准格式的隧道与代理指标。
4. **Given** 配置被拆分为主文件与若干包含文件，**When** 启动客户端与服务端，**Then** 行为与合并成单文件时一致。
5. **Given** 一个只提供静态文件的内网目录、一个只做 SOCKS5 的本地服务、一个只监听 Unix 域套接字的服务，**When** 分别通过插件方式暴露，**Then** 三者都能被正常访问而无需额外自建服务。

---

### Edge Cases

- 同一域名的 `http` 与 `https` 代理分别注册：应被允许（监听端口不同、证书不同），且互不抢占。
- 注册了 vhost 代理但服务端未配置对应的 vhost 监听端口：注册必须失败并给出明确原因，而不是"注册成功但访问不通"。
- 通配域名与精确域名的优先级：精确匹配必须优先于通配匹配。
- 请求路径级别的路由（frp 的 `locations`）：域名匹配到多个代理时的处置必须确定且可解释。
- 大请求体与流式响应：不得整体缓冲后再转发，否则大文件与大响应会撑爆服务端内存。
- 内网服务在转发中途断开：访客必须收到明确的连接终止，服务端不得挂住半开连接。
- 客户端请求自动分配端口但授权区间已耗尽：必须失败并给出原因（而非静默回落）。
- 限速与压缩同时开启：限速必须作用于隧道内的实际字节，而非原始载荷。
- 健康检查探针本身不应被限速、压缩或 PROXY 协议头污染（否则探针永远失败）。
- UDP：单个数据报超过隧道单帧上限时的处置必须明确（丢弃并计数，或分片重组），不得静默截断。
- 重载配置时删除了一个正在被访问的代理：在途连接按既定语义走完或明确终止，不得悬挂。
- 管理接口与数据面共用端口：不允许，管理接口必须能独立关闭。

## Requirements *(mandatory)*

### Functional Requirements

**域名路由的 HTTP/HTTPS 代理**

- **FR-001**: 系统 MUST 允许客户端注册 `http` 类型代理，声明一个或多个自定义域名，且该类型不占用公网端口资源。
- **FR-002**: 服务端 MUST 在配置的 vhost HTTP 监听端口上接受 HTTP/1.1 与 HTTP/2 请求，按请求的 `:authority`（去掉端口后）匹配已注册域名后转发。
- **FR-003**: 系统 MUST 允许注册 `https` 类型代理；服务端 MUST 在 TLS 握手阶段按 SNI 选择该域名的证书并终止 TLS，再以明文 HTTP 转发给客户端本地服务。
- **FR-004**: 转发 MUST 保留请求方法、路径、查询串、请求头与请求体，以及响应状态码、响应头与响应体；MUST 对未知的 hop-by-hop 头做正确处理而非原样透传。
- **FR-005**: 服务端 MUST 向客户端转发的请求附加 `X-Forwarded-For`（访客地址）与 `X-Forwarded-Proto`（原始协议）。
- **FR-006**: 未匹配任何已注册域名的请求 MUST 返回 404，且 MUST NOT 回落到其他代理或默认后端。
- **FR-007**: 域名冲突（两个会话声明同一域名）MUST 在注册阶段拒绝后者，返回明确的失败原因，且不影响先注册者的映射。
- **FR-008**: 服务端 MUST 支持统一子域名后缀配置；配置后客户端只需声明子域名标签即可完成注册。
- **FR-009**: 域名授权 MUST 复用既有的每用户 vhost 授权规则（精确匹配，或 `*.domain` 通配且只匹配恰好一层左标签）。
- **FR-010**: 客户端 SHOULD 支持以 HTTPS 访问本地服务（内网服务为 TLS 的场景），使访客侧协议与本地服务侧协议可以不同。
- **FR-011**: 端到端 HTTP 转发 MUST 采用流式处理，MUST NOT 将请求体或响应体整体缓冲后再转发。

**UDP 代理**

- **FR-012**: 系统 MUST 允许注册 `udp` 类型代理并绑定服务端 UDP 端口，端口授权复用既有的每用户区间规则。
- **FR-013**: 系统 MUST 按"外部源地址+源端口"识别 UDP 会话，同一会话内的数据报双向转发且保持数据报边界。
- **FR-014**: UDP 会话 MUST 有空闲回收策略且其阈值可配置，回收后同源端口再次发包应能重建会话。
- **FR-015**: UDP 代理 MUST 与隧道承载方式解耦——在既有的两种承载路径上行为一致。
- **FR-016**: 单个超出隧道单帧上限的数据报，其处置 MUST 有明确定义并可观测（丢弃并计数，或分片重组），MUST NOT 静默截断。

**转发选项与可用性**

- **FR-017**: 客户端 MUST 支持为单个代理开启载荷压缩，且压缩只作用于该代理的隧道流量。
- **FR-018**: 代理 MUST 支持带宽限制，阈值按代理配置，且限制作用于该代理在隧道内的实际传输字节。
- **FR-019**: 客户端 MUST 支持让服务端在转发业务数据之前发送 PROXY 协议头（v1 与 v2），供内网服务获取真实源地址。
- **FR-020**: 系统 MUST 支持对客户端本地服务做周期性健康检查；连续失败达阈值后该代理拒绝新接入，恢复后自动重新接入，全程无需重启客户端。
- **FR-021**: 健康检查探针流量 MUST NOT 受该代理的压缩、限速与 PROXY 协议头设置影响。
- **FR-022**: 系统 MUST 支持将多个同名代理组织为负载均衡组，并按配置的策略在组内选择后端。
- **FR-023**: 服务端 MUST 支持客户端不指定端口（留空或填 0）时的自动端口分配，并把实际分配的端口回告客户端；分配结果 MUST 落在该客户端的授权区间内；区间耗尽 MUST 失败并给出原因。
- **FR-024**: 同名代理冲突的处置策略 MUST 可配置，且客户端必须能明确感知注册结果是"拒绝"还是"抢占"。
- **FR-025**: 系统 MUST 支持基于请求路径的路由细化（当一个域名下注册了多个后端时），匹配优先级必须确定且可解释。

**点对点与密钥保护的穿透**

- **FR-026**: 系统 MUST 支持密钥保护的 TCP 代理类型：不在公网开放端口，访问方需持有与发布方一致的密钥才能接入。
- **FR-027**: 系统 MUST 支持密钥保护的 UDP 代理类型，语义同 FR-026。
- **FR-028**: 系统 SHOULD 支持在 NAT 条件允许时建立端到端直连；打洞失败时 MUST 自动回退到服务端中转路径，而不是直接失败。
- **FR-029**: 密钥不匹配的接入尝试 MUST 被拒绝，且响应不得泄露发布方是否存在以外的信息。

**运维面**

- **FR-030**: 服务端 MUST 提供管理接口，默认只监听本机并要求凭证；MUST 能给出代理列表、会话列表与流量统计。
- **FR-031**: 服务端 MUST 提供只读的可视化界面用于查看代理与会话状态。
- **FR-032**: 服务端 MUST 暴露标准抓取格式的运行指标（连接数、流量、会话、代理状态）。
- **FR-033**: 客户端 MUST 支持不重启进程重载配置：新增与变更的代理生效、删除的代理下线、在途转发连接按既定语义处理且不悬挂。
- **FR-034**: 配置 MUST 支持拆分为多个文件并在启动时合并，合并后行为与单文件一致。
- **FR-035**: 系统 MUST 提供插件机制，至少覆盖：把内网明文 HTTP 服务以 HTTPS 暴露、把内网 HTTPS 服务以明文 HTTP 暴露、暴露静态文件目录、暴露 SOCKS5 服务、暴露 Unix 域套接字服务。

**已知债务的不可回退约束**

- **FR-036**: 上述所有新增能力 MUST 保持既有协议语义不回退：帧格式、认证与授权模型、TLS 默认加密、`conn_id` 分配方式、以及"连接活性交给传输层"的决策。

### Key Entities

- **代理（Proxy）**：客户端的一项注册声明，把服务端的某个入口（端口或域名）映射到客户端本地服务。关键属性：名称、类型、本地地址、入口标识（端口 / 域名 / 子域名标签）、转发选项、健康检查与负载均衡归属、所属会话。
- **会话（Session）**：一条已认证的控制连接，代表一个客户端实例。持有身份（用户或 legacy）、注册的代理集合、数据通道的建立方式（TCP 回连或 QUIC 开流）。
- **身份（Identity）**：由 token 解析出的授权主体，决定可用于哪些端口区间与哪些域名。
- **域名映射（Vhost Mapping）**：域名 → 代理的映射项，含精确与通配两类，冲突与优先级规则作用于此。
- **UDP 会话**：由"外部源地址+源端口"标识的转发表项，带最后活动时间与空闲回收阈值。
- **负载均衡组**：由名称与分组键标识的一组同类代理，按策略选择后端。
- **管理接口与指标端点**：只读的运维观测入口，与数据面在监听与鉴权上相互独立。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 与 frp 的功能差集中，本规格 P1–P3 覆盖的项全部可用；P4–P5 覆盖项实现后，差距清单剩余项仅限"明确不复刻"清单（见附录 A.4）。
- **SC-002**: 一个已在用 frp 的运维者，在只改配置文件的代理类型声明与入口字段的前提下即可迁移，无需改动服务端的配置结构（vhost 监听端口等新增项除外）。
- **SC-003**: 既有 23 项测试在全部改动完成后仍全绿；本规格每一项新增能力至少伴随一条端到端测试。
- **SC-004**: 反向代理类场景（域名路由）下，访客侧观测到的附加延迟相对直连内网服务不超过一个可感知阈值（服务端与内网服务同城部署时，P95 附加延迟 < 50ms）。
- **SC-005**: 公网 QUIC 路径完成验证（打通 UDP 端口放行后，控制与数据通道在公网环境下均走 QUIC 且 0-RTT 重连可用），M2 遗留阻塞清零。
- **SC-006**: 单机在 500 个已注册代理、2000 条并发转发连接的规模下，管理接口 P95 响应时间 < 1s，且新增代理的注册流程不阻塞既有转发（既有转发在注册期间的成功率不下降）。
- **SC-007**: 端到端 HTTP 转发在传输大体积请求体与流式响应时，服务端进程内存占用不随载荷大小线性增长——转发 1GB 与转发 1MB 时的常驻内存增量处于同一量级。

## Assumptions

- 目标用户是有内网穿透自建经验的运维者，熟悉 frp 的配置心智，迁移成本主要由"配置字段是否被支持"决定，而非由术语差异决定。
- 明确**不复刻**的 frp 机制（复刻为负收益，见附录 A.4）：`tcp_mux` 与连接池（由 QUIC 原生多路复用取代）、传输层加密开关（TLS 1.3 / QUIC 内生加密，无明文模式）、`transport.protocol = quic` 配置项（已原生使用且带 0-RTT）、应用层心跳（连接活性交给传输层）。
- HTTP/3 网关（M3）**不在本规格范围内**，它将在本规格的 US1（域名路由）之上以独立规格推进；本规格为它的前置条件。
- 服务端与客户端同版本演进：新增能力通过既有版本协商机制（主号一致即可互操作）承载；旧版客户端注册本规格新增的代理类型应得到明确的失败原因，而非静默降级。
- 证书方面，本规格只要求"服务端能按 SNI 选中并终止证书"；证书的来源可以是手工配置，自动化签发属于 M3 的范围。
- 域名与端口的冲突策略默认采用"拒绝后来者"，抢占为可选配置；具体默认值在规划阶段确定。
- 空闲回收、健康检查、限速等阈值的默认值在规划阶段确定，本规格只要求它们可配置且行为可观测。
- 已知遗留阻塞：M2 的公网 QUIC 验证受制于云服务器安全组（UDP 端口未放行），该项不属于编码工作，见附录 A.5。
- 排期顺序（P1 → P5）是本规格的优先级排序，不代表交付承诺；实际推进顺序在规划与任务拆解阶段确认。

### A.4 明确不复刻（结构上已被取代）

| frp 机制 | Rust-FRP 的取代物 | 理由 |
|---|---|---|
| `tcpMux` + `poolCount` 连接池 | QUIC 原生 bi-stream，开流零成本 | M2 决策：隧道内不需要多路复用层，池化无收益 |
| `transport.useEncryption` | TLS 1.3 / QUIC 内生 TLS | 决策记录：无明文模式，加密不可关闭 |
| `transport.protocol = quic` 配置项 | 已是原生传输，且带 0-RTT 与断线重连 | M2 决策：QUIC 优先 |
| 应用层心跳 | 传输层 keepalive | 决策记录：连接活性交给传输层 |
| 端到端 QUIC 透传型 HTTP/3 | 边缘终止型 HTTP/3（M3） | M3 决策：收益集中在用户↔frps 一跳 |

### A.5 遗留阻塞（非编码工作）

| 项 | 现状 | 影响 | 归属 |
|---|---|---|---|
| 公网 QUIC 验证 | tryanderror.cn 的 UDP 端口被云安全组拦截（tcpdump 已确认） | M2 无法完成公网验收，生产默认仍走 TCP | SC-005；需在云控制台放行 |
| 生产切换 | jyutyu.cn 生产隧道仍为 TCP 传输 | QUIC 的收益未在生产兑现 | SC-005 完成后推进 |
| ACME 证书自动化 | 未实现，且现有 ACME 工具的云厂商密钥已失效 | 阻塞 M3 的开箱即用体验 | 独立规格（M3） |
