## 3. 发现

### F1 同域名的 `http` 与 `https` 代理被判成冲突（已修）

spec.md 边界情形写明"同一域名的 http 与 https 代理分别注册**应被允许**（监听端口不同、
证书不同），且互不抢占"，但路由表键只有域名、没有类型，第二条注册被当成冲突拒绝。

**修**：键改为 `(ProxyType, 域名)`；`ProxyType` 加 `Hash`；`VhostKey` 带 `kind` 供会话结束
精确清理。回归防线：`router::tests::same_domain_serves_both_kinds` +
e2e `vhost_same_domain_http_and_https`。修复后真实链路复测：两条代理都注册成功。

### F2 h2 访客请求到 origin 丢了 Host（已修）

HTTP/2 没有 `Host` 头，authority 在 `:authority`（hyper 映射到 `uri.authority()`），
而转发头只遍历 header 表 → h2 请求的 Host 整个丢失。同一个 TLS 监听上：
`curl --http1.1` 有 Host，`curl --http2` 没有。

**修**：剥离逐跳头后若无 `host` 项，从 `uri.authority()` 补回（RFC 9113 §8.3.1 的
h2→h1 转换语义）。回归防线：e2e `vhost_http2_authority_becomes_host`（h2c）。

### F3 大响应被静默截断（**未修，阻塞**）

| 载荷 | 收到 / 请求 | 耗时 |
|---|---|---|
| 8 MiB | 7,845,336 / 8,388,608 | 9.8s |
| 32 MiB | 30,085,803 / 33,554,432 | 14.9s |
| 64 MiB | 63,500,676 / 67,108,864 | 25.6s |

**对照组排除隧道层**：同一隧道的 `tcp` 代理拉 64 MiB 完整无损（67,108,864 字节）。
绕过 nginx 直连 rfps:8080 仍然截断 → 缺陷在 HTTP 桥接层。

**定位**（临时插桩，已移除）：

```
客户端: 响应体回写结束 written=8388608            ← 写全了
服务端: 隧道读错误 bytes=5660672 ECONNRESET       ← 只读到 5.6 MiB
```

客户端关闭前插 5 秒延迟 → 8 MiB 完整送达。**根因**：服务端在请求体泵完就
`shutdown(Write)` 半关闭，客户端因此无法感知对端何时读完响应体（读方向早已 EOF），
关闭 socket 时仍有约 2.7 MiB 在途，内核发 RST 丢弃尾部。

**修法**（见 [research.md D11](../research.md)）：两个方向都改为显式分帧
（`元数据帧 → N 个长度前缀体帧 → 0 长度帧`），不再用半关闭表达体结束；客户端写完
响应后等对端关闭再释放 socket。属契约修订，未在本轮实施（收敛任务 T108–T113）。

### F4 注册期与控制消息存在竞态（未修）

观察到的日志：

```
WARN rfp_client: control connection lost, retrying in 5s
  error=unexpected register reply: Some(NewConnection { conn_id: 1, proxy_name: "vhost-tls", http: Some(..) })
```

客户端的注册循环用"下一条消息必须是 `RegisterProxyAck`"来等待应答；若此时恰有访客请求
命中网关，服务端会先发 `NewConnection`，客户端即判定为异常应答并**断开整条控制连接**。
表现为：rfps 重启后首个请求期间注册会失败并触发重连。

### F5 单个代理注册失败会拖垮整个会话（未修）

`big-tcp` 因端口越权注册失败时，客户端把它当 `Retry`，于是**整条会话断开重连**，
其余代理一起掉线（日志里可见连续三轮）。一个配置错误的代理不该影响其他代理。

### F6 `subdomain_host` 的 TOML 段陷阱（文档级）

`subdomain_host` 写在 `[https]` 段之后会被 TOML 归入该段，根级就没配上，
报错却是"服务端未配置 subdomain_host"，容易误判成代码问题。本轮实际踩到。
已在 `docs/CONVENTIONS.md` 的部署状态里记录正确写法。
**后续（2026-10-12 晚，T117）**：已改为解析期直接报错（两侧全部配置结构体加
`deny_unknown_fields`），错位/拼错的键会当场点名；不采用 `[vhost]` 子表方案，
因为它要求改动已发布的配置格式而收益相同。实测见 §7.1。
